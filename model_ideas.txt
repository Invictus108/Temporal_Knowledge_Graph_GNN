Goals: model can predict new edges in a graph over time
   - This will likely involve merging a GCN (likely attention based) with a recurrent model, likely an LSTM

Notes: Model will be created with global node pool. Some nodes will be unconnected. This is ok.

First need to consider how to represent the text in edges and nodes

Edge embeddings

  - embeddings will be learned by the model
  - Ex: born, died, friends, enemies, killed_by, etc

Then how to rep node text:

2 options
   - One-hot encoding (in hindsight I dont think this is plausible. Too little info)
      - Pros
        - Easy decode rule (take softmax and sample probabilities)
        - Super easy to implement (nn.Embedding layer)
      - Cons
        - Less representative and would probably worsen the model
        - Can get big fast because of the copious amount of proper nouns in the dataset
   - Actual embedding layer
      - Generate separate embeddings for different characteristics 
        - name
        - description
        - class
      - embeddings will be merged in an embedding layer in the model
      - Pros
        - Much more representative
        - Size is more manageable
      - Cons
        - Much more difficult to implement
            - imported models will probably struggle with this task because of all the proper nouns,
              but adding our own embedding layers will make the model more expensive and difficult
                - create node embeddings with description integrated for better preserved meaning


The best idea is to go with multiple pretrained embeddings of names, class, and description. 
Then put an embedding head that takes in each embedding vector, synthesizes it and projects down into GNN dim
   - dataset will be a concatenation of the three because we can just leave it as the concat or project down


Text embedding could also be merged with structural embedding in some way, but the structure will probably be learned via
convolutions so its probably ok.

With embedding taken care of each node will be represented by an embedding and we have the starting structure for the graph.

Embeddings layer:
  - simple MLP that takes all the embedding vectors representing a model and projects them into hidden dim


Update Rule: h(t+1)_i = Non-Linearity(Sum(a_ij * m_ij)) where a_ij is an attention score and m is message (linear combination of messages)
   - attention scores are calculated by a_score_ij = Non-Linearity(a(z_i, z_j, edge_ij)) where a_ij is attention score, a is learned attention function and
     z is W_n * h. Do it only over neighbors
     - gotta do softmax to get a_ij
   - messages (need a way to synthesize edges and nodes)
     - m_ij = W_h * h(t)_j + W_r * edge_ij
   

- Multi head attentions should be considered after single head is finished. Basically the same thing but project down and concat
  - dim has to be divisible by number of heads
  - Same set of the above equations for each head (so head has separate, W_h, W_r, etc scaled down to project into dim/# heads)
  - at end concat output of each head for full
  - for efficiency can use the same weights for all heads. Its not as powerful as full multi-head attention, but it still captures
    different relationships

Further considerations
   - since we are using sum should probably use layer norms to keep things from exploding and maybe residuals
   - Something like this
     h(t+1) = GNNLayer(h(t))
     h(t+1) = LayerNorm(h(t+1) + h(t))
      - Note: if using multi head attention need to project h(t) down
   - can also add a feedforward network after attention like GNNs
     h(t+1) = LayerNorm(h(t+1) + MLP(h(t+1)))
   - dropouts could also be useful for better generalization 


Running this for a bit will give us rich contextual embeddings for each node, which we can then use for link prediction and node gen

First update LSTM hidden strategies
  - Two ways to do this.
    - 1: Full graph embeddings
      - x = ReadOut(H) # convert graph to vector for LSTM
        - probably attention pooling
          - compute attention score and readout becomes a linear combination of node embedding weighted by attention scores
          - can also be conditioned on LSTM hidden state
      - Standard LSTM update using x
      - Problem with this is that it captures global patterns but loses fine-grained info from singular nodes
    - 2: Store a hidden state for each node
       - normal LSTM update conditioned on the node's hidden state
       - Stores much more fine-grained info, at the cost of not having as strong a representation for the graph as a whole 


Link prediction
   - strategies
      - 1: predict only changes
        - All current triples are passed to the next graph
        - the model solely predicts additions to the graph
           - make 2 seperate scoring heads, one for deletion and one for addition
            - candidates are the true positives (things added or deleted), combined with a equal number of sampled negatives
            - loss is calculated and backpropagated
            - deletions and additions are added
      - 2: Predict entire graph 
        - Nothing is passed to next graph
        - Candidate set includes all current triples in graph + potential candidates
          - Sample equal sizes from both current and proposed to have equal pos-neg class count
        - Benefits
          - Allows for removals of edges
          - simpler to implement
        - Drawbacks
          - considering most edges are persistent this could result in the model learning all current edges stay which is not what we want
            - could be resolved by shuffling candidates
   - Split into two parts
   - 1: Candidate proposal
      - need to consider possible edges between node i and node j
      - candidates include nodes not currently connected but in candidate pool
        - allows for connecting unconnected nodes
        - replacement for pure node gen 
          - easier than pure node gen (dont need language models)
          - Allows users to define character set
      - has to be over a subset of nodes and edges or it becomes unfeasible
          - If going with strategy 2, candidate set starts with all current triples
          - strategy classes are instantiated in the candidate collection class
          - node sampling strategies (candidates j for each i)
            - random (probably a bad idea but a bit of noise isnt bad)
            - neighbors (selection of nodes of depth 1-3 away from i)
            - embedding similarity (dot product with node embedding matrix (could be expensive))
          - edge sampling
            - total random (probably a bad idea but a bit of noise isnt bad)
            - build counts of edges in neighbors and sample probabilistically from it based on count (with noise)
              - count could also be based off how good edge is, so MLP(i , j, edge) but that might be too expensive
            - TODO: need more possibilities
        
   - 2: Candidate scoring 
      - batch all triplets into single tensor and pass to scoring MLP
      - Feed (i, j, edge, i_hidden, j_hidden) into a basic MLP and get a score
        - condition on LSTM hidden states for more context
        - MLP(i , j, edge, i_hidden, j_hidden)
      - Apply sigmoid to get probs
      - possible link selection strategies (should it be allowed to create more than one link per timestep?)
          - anything that passes a certain threshold (variable multi link)
          - top k (fixed multi-link)
          - apply softmax and sample probabilistically (variable multi link)
      - add to graph tables


Loss:
  - Binary cross entropy with the next graph
  - existing edges are labeled one and ones that dont exist are 0
  - this will hopefully capture loss for both negative and positive samples


Generation:
  - Autoregressive generation
    - sample candidates based on probabilities output by forward pass
  - Start with one graph, run the network over it to get the next, then pass that graph back into the model and so on
